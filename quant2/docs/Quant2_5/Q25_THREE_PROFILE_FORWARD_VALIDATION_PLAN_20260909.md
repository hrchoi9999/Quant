# Quant 2.5 세 모델 실제 데이터 모의운용 검증 계획

2026-09-11 문서 정리. **전략·평가 규칙과 미확정 제안을 보존한 기술 참조 문서**다. 현재 완료/미완료는 [진행 현황](QUANT_2_5_PROGRESS.md), 실행 승인은 [승인 근거](Q25_STAGE_1_5_USER_AUTHORIZATION_20260910.md)에서 확인한다. 본문 중 최초 계획의 ‘제안’은 자동으로 확정되지 않는다. 이후 실제 승인·검수된 항목을 예전 문구 때문에 다시 미승인으로 되돌리지 않는다.

과거 날짜별 실행안·사전점검·완료 추기는 [정리 전 원문](archive/guidance_cleanup_20260911_01/Q25_THREE_PROFILE_FORWARD_VALIDATION_PLAN_20260909.md)에 보존했다. 아래 1~7절의 전략·측정·평가 내용은 원문 그대로 유지했다.

## 사용자 확정 평가 구간 — 2026-09-10

세 모델 모두 **2026-09-04까지 백테스트, 2026-09-07부터 Live 성능평가 구간**으로 구분한다. 사용자 최신 지시 "깔끔 하게 9월 4일이 금요일이니까 4일까지만 백테스트로 하고 7일 부터는 Live 성능평가로 하자."를 반영한다. 설정은 `quant2/config/quant25_evaluation_periods.json`의 REV2이며 이전9/7종료·9/8시작 정책을 대체한다. 이전 경계와 정책SHA는 supersedes에 보존한다. 9/5~9/6은 두 평가구간 사이로 표시하며 Live 표본으로 세지 않는다. 이 기간 확정은 미정 성과/위험 임계값을 확정하지 않으며 별도의 사용자 포괄 실행 승인 범위는 해당 승인 문서를 따른다.

Live는 실제로 관측한 자료·의사결정·보유/모의체결에 기반한 모의운용 성과이며 실거래 체결을 뜻하지 않는다. 평가구간 시작일9/7과 실제 검증 가능한 최초 관측·결정·모의체결 시각은 별도로 기록한다. 9/7 이후라도 당시의 입력·동결 전략·결정/초기보유·체결 또는 미체결·평가 근거가 없으면 `live_window_unverified`로 남기고 수익률은null이다. 이후 재계산 결과는 `retrospective_reconstruction_not_live`로 별도 표시한다. 기간을 뒤로 이동해 미확인 날짜를 숨기거나 결측을0%/전일값으로 메우지 않는다.

9/7 일별수익률에는 직전 거래일9/4 종가의 검증 가능한 NAV와 실제 이어진 보유/현금 기준이 필요하다. 백테스트9/4말 보유를 실제초기보유처럼 자동 이월하지 않는다. 기존 장부의9/10 실제 생성시각과 이력은 보존한다. 신규입력 준비와 관측을 계속하면서 실제증거가 있는 날짜부터 검증 실적을 표시한다. 백테스트와 Live 수익률을 분리하고 연결 그래프가 필요하면 경계와 미확인 구간을 명시한다.

기존 연구 보고서의 종료일/수익률을 덮어쓰지 않는다. 이전의9/7까지 백테스트 연장 작업은 이번 변경으로 취소한다. 보완 가격으로 재평가가 필요한 경우에도9/4까지만 별도 run으로 계산해 기존 결과와 비교한다.

## 1. 목적·승인 범위

공격형 유지·방어형 PG 유지·방어형 주식 축소 유지의 세 모델을 실제로 도착하는 새 데이터로 관찰합니다. 검증할 질문은 **동결한 전략을 정확히 실행하는가, 비용 후 수익과 감수한 위험이 각 모델의 목적에 부합하는가, 일반 투자자에게 일관되게 설명할 수 있는가**입니다. 세 모델 중 하나만 뽑거나 짧은 기간의 수익 순위로 나머지를 폐기하지 않습니다.

9/9 최초 작성 시 승인은 계획 수립이었으며 이후 별도 승인된 운영 입력 복구·비공개 관측 준비는 각각의 작업기록을 따릅니다. 9/10 사용자 확정으로 평가 구간 경계는 위와 같이 적용합니다. 아래 별도 확정되지 않은 기간·성과/위험 판정 수치는 여전히 제안입니다. 실제 관측·의사결정·모의체결 시작시각은 검증된 기록으로만 표시하고 평가구간 시작일로 소급하지 않습니다. 이 평가기간 결정 자체는 실거래, 정기 실행 등록, 공개 게시, Migration 후 페이지 정비의 실행 승인이 아닙니다.

기존 자산: [세 모델 동결](QUANT_2_5_THREE_PROFILE_FREEZE_20260909.md), run_03의 freeze_manifest/ execution_contract, [거래정지 정책](QUANT_2_5_TRADING_HALT_POLICY_V1_20260907.md), [시장 대조 결과](../../reports/quant2_0/q25_market_control_20260908/RESULT.md), [OS 준비 문서](Q25_OS_THREE_PROFILE_ADAPTER_PREPARATION_20260909.md). 구 버전1.2의 180일 승인 규정을 2.5 확정 규칙으로 복사하지 않습니다.

## 2. 세 모델과 동결 경계

| 모델 | 유지할 전략 | 검증의 중심 |
|---|---|---|
| 공격형 `activity_retention` | 주식 최대20개, 종목당 목표5%, 주식 목표상한100%, ETF 없음 | 높은 수익의 대가로 부담한 낙폭·하락기간·집중도가 사용자가 수용할 수준인지 |

목표 상한은 일별 평가비중 강제 상한이 아닙니다. 특히 ETF 목표5%를 가격상승 후 강제로5%로 되돌리는 새 전략을 도입하지 않습니다. 총30개에는 거래정지 잔류 보유도 포함합니다. 방어형의 업종 레버리지 자금 차감·ETF 유지·현금 배분은 동결 실행 계약을 그대로 재사용합니다.

주식/업종 ETF 선정은 주간, 기본 방어 ETF는 완료 월말 신호, 실제 주식·ETF 통합 비중 조정은 주간입니다. 기준은 수요일 종가 판단(휴장이면 직전 거래일), 이미 이용 가능한 직전 거래일 QM 상태, 다음 거래일 시가입니다. 실제 입력이 늦으면 과거 마감으로 소급하지 않습니다. 신호 마감·허용 지연·다음 처리 시각은 시작 전에 실제 Harness/OS 일정으로 확정합니다.

평가 도중 점수·종목 수·비중·유니버스·교체/위험 규칙을 수익에 맞춰 바꾸지 않습니다. 행동이 달라지는 수정은 새 동결 ID와 이후의 새 관찰 구간으로 분리하고 기존 손실 구간을 보존합니다. 동일 출력을 보장하는 오류 수정도 변경 전후 증거를 남깁니다. 반복 탐색으로 과거 성과가 부풀려질 수 있다는 연구를 고려한 설계입니다. [Bailey 외, The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf).

## 3. 시작일과 관찰 기간 제안

평가구간 시작일 `T0`는 사용자 최신 확정에 따라 **2026-09-07**입니다. 실제 검증된 관측 시작일과 모의 체결 시작일은 별도 기록하며 T0로 소급하지 않습니다. 아래 제안의 유효 관측·결정·월말 신호 횟수는 실제 근거가 있는 기록만 집계합니다. 첫 체결 전에도 검증된 현금 대기 상태가 있으면 기록하지만, 존재하지 않은 과거 장부를 현금대기로 만들어 채우지 않습니다. 기존 합성 run_01~03, 재구성 QM 과거 상태, 이미 본 백테스트는 전진 실적이 아닙니다. 과거 모멘텀/이동평균 입력을 향후 결정에 사용하는 것과 과거기간 수익을 실제 실적으로 붙이는 것은 구분합니다.

| 검토 시점 제안 | 필요한 관측 | 판단할 내용 | 판단하지 않는 것 |
|---|---|---|---|
| 초기 운영 점검 | 대략 첫1개월, 유효 주간결정4회 및 시작 후 새 월말 ETF 신호1회 이상 | 지연·휴장·미체결·현금·장부·화면 정보가 계약대로 작동하는지 | 수익 우위·전 국면 대응 검증 완료 |

기간과 횟수는 이번 계획의 운영 제안이며 통계적으로 충분하다고 증명된 표본 수가 아닙니다. 휴장·시작일 위치 때문에 실제 일정은 길어질 수 있습니다. 거래가0건이어도 유효한 결정은1회로 집계하고 재실행을 추가 표본으로 세지 않습니다. 입력 미확인/무효 결정은 유효 횟수에 넣지 않되 실패와 기간은 기록합니다.

관찰 중 하락 국면이 거의 없으면 방어 성능은 미확인입니다. 국면별 거래일수와 독립적인 연속 구간 수를 보고하고 필요 시 관찰을 연장합니다. 유리한 국면만 떼어 통과시키지 않습니다. 필요에 따라12개월 이상 관찰하되 결과가 좋아질 때까지 종료일을 임의로 이동하지 않습니다. 최근1년 한정은 과거 종목 수 확대 실험에 대한 지시였으며 전체 모델 검증 상한이 아닙니다.

20bp와30bp는 같은 전략의 비용 조건이며 새 전략 두 개가 아닙니다. 현금 제약으로 주수·경로가 달라지면 각 비용 조건에 따른 장부를 유지합니다. 동일 매매의 비용 차감만 한 결과는 별도 ‘매매 고정 민감도’로 표시합니다. 미래 체결일 전체 거래량을 주문 결정 시점의 정보처럼 사용하지 않습니다.

실제 데이터 모의운용도 모의운용입니다. 정보서비스 사용자별 체결가격·계좌 수익·실거래 수익을 대표한다고 표시하지 않습니다.

## 5. 비교 대상·핵심 측정값

세 모델과 비교 장부는 같은 T0/종료일/자료 기준으로 평가합니다. 비교 대상을 사후에 바꾸지 않습니다.

- 시장 기준: 기존 연구의 **KODEX200(069500) 단순 보유**를 재사용. 같은 최초 매수 시점과 비용률, 실제 발생한 거래만 비용 차감. 모델의 매매 횟수를 강제로 맞추지 않음.
- 선정 기여 기준: 각 모델의 주식 부분만069500으로 바꾸고 목표 주식비중·기타 ETF·현금 정책·결정/체결 시점을 맞추는 기존 대조 원리를 재사용. 원주식과 ETF의 정수 단위 차이/잔여현금은 실제 장부로 보고. 같은 목표노출 비교이지 동일 베타·동일 위험 보장은 아님.

## 8. 수동 수집과 실행시점 연결

- 사용자의 명시적 명령으로 새 수집을 시작한다. 수요일 종가 ETF 자료는 목요일 오전부터 수집 가능하다. Harness D−1 정책은 유지하며 목요일 자동 수집을 전제하지 않는다.
- 위 동결 전략의 ‘다음 거래일 시가’와 현실의 실제 수집·결정 시각 충돌은 실행 계약 후보로 분리하여 검증한다. 과거 신호일로 수신을 되돌리거나 이미 지난 시가로 체결하지 않는다.
- 현재 TEST_ONLY 후보: 신호일과 입력 범위는 유지하고 실제 수집/필수입력 가용 → 결정 → 발행/가시화 → 미래 정규장 시가를 연결한다. 다음 정규 주간 신호 종가에 옛 미봉인 신호를 만료시키고 첫 실행 시가도 만료 전이어야 하는 안을 검증한다. 운영 채택 전이며 임의의 추가 2시가 제한은 없다.
- capture/export/selector/forward 및 월말 경계를 함께 검수한다. 월말 주간 결정에는 해당 완료 월말 입력이 필요하며 이전 달 목표로 대체하지 않는다. 실제 수신 시각·휴장·권리 영향·만료·중복 방지를 검사한다.
- 최초 월간 입력 생산/수신은 이미 검수 완료했다. 현황과 증거는 진행 문서에만 유지하며 여기서 재실행을 지시하지 않는다. 전체 9입력·첫 실제 결정/체결 완료와 구분한다.
- 관찰 기간·성과/위험 임계값·출시 기준의 제안은 별도 확정 대상이다. 이를 비공개 입력 준비를 중단하는 새 조건으로 확대하지 않는다. 실제 선정/체결·운영 반영은 필요한 입력·계약·검수 및 해당 승인 조건에 따라 판단한다.

## 9. 최초 calibration 학습 입력의 현재 관측 근거

- 사용자 후속 결정: ①2.5가 사용하는 기존1.0 프로그램·데이터의 우선 점검·정비·수정을 포함한2.5 업그레이드 완료 → ②나머지1.0 프로그램 오류 점검 → ③AI 학습 모델 검토·보완 순서다. AI 효용성 평가·추가개발·학습은 세 번째로 진행한다. 아래는 완료된 입력 준비의 의미를 보존하는 계약이며, 관련 추가개발·최초fit·운영연결의 현재 실행계획이 아니다. 해당 후속 작업은 보류한다.
- 과거 최초 수신시각이 없는 저장 자료는 과거 PIT/Live 재현의 증거로 사용할 수 없다. 현재 실제로 읽어 별도 파일로 고정한 자료는 그 관측 이후의 학습 입력 준비 대상으로 검수할 수 있다. 이는 실제 학습·학습 주기 변경·운영 적용 승인이 아니다.
- 우선 기존 소비 필수 ALL/KOSPI/KOSDAQ ×20d 3그룹만 준비한다. 원천 값·기준일·NULL을 유지하고 원본 DB/CSV를 수정하지 않는다. label 종료일·기준일은 완료된 수집 목표 범위 안에서 검증하며 표본수는 결합·유효성 검사 후 다시 센다.
- 새로 고정한 입력 파일별 원천/조회 조건/행수/hash와 실제 읽기·파일 저장·검증 완료시각을 기록한다. `availability_basis=verified_current_snapshot`으로 구분하고 원래 최초 가용시각은 미확인으로 유지한다. 기존 점검 보고 시각이나 생성일을 이번 관측시각으로 복사하지 않는다.
- 후속 학습용 파생 입력의 `feature_available_at`/`target_available_at`는 이 계약에서 해당 값이 현재 스냅샷에 존재함을 확인한 시각을 뜻한다. 실제 봉인된 스냅샷과 행별 값 연결 및 관측 근거가 있을 때만 생성한다. 과거 최초 수신시각이라는 뜻으로 사용하지 않으며 이 의미와 hash를 artifact에도 보존해야 한다. 과거 시점 평가에서는 이 근거 유형을 허용하지 않는다.
- 실제 fit cutoff는 모든 입력의 관측·봉인 이후여야 한다. 최초 계수 생성은 허용된 학습 시점·범위의 별도 실행 판단 후 수행한다. 적용 가능한 decision은 계수 생성·검수·운영 연결 이후의 실제 전진 시점이며 9/10 과거 결정·성과를 복원하지 않는다. 학습 표본의 과거 feature 재현성·개정 가능성과 성능은 별도 검증 문제로 남는다.
- QM은 원천 연결·입력 준비, OS는 운영 입력·시점 의미 검수, 총괄은 검수 취합과 실제 학습/연결 판단을 담당한다. 현재 스냅샷 준비만으로 WD02 또는 전체 cycle을 완료 처리하지 않는다.
