# QS-Master Investment Status Web Request

QS 요청 제출처: QS-Master  
권장 담당 쓰레드: QS-Platform-Auth, QS-Public-Web, QS-Quant-Handoff  
공개 반영 포함 여부: No  
Admin only 여부: No  
관련 시스템: Quant Trading, QuantService

## 작업명

- 로그인 사용자 전용 `투자 현황` 메뉴 및 `가상투자/실투자` 페이지 반영

## 요청 출처

- Quant Trading thread

## 작업 목적

redbot.co.kr에서 로그인한 사용자가 자신의 투자 현황을 직접 입력하고 확인할 수 있는 사용자 전용 페이지를 추가해 주세요.

이번 요청은 공개 모델 정보 페이지가 아니라:

- 로그인 사용자만 접근 가능하고
- 사용자별 데이터가 다르며
- 실제 입력한 거래내역을 바탕으로
- 현재 평가손익을 계산해 보여주는

개인화 투자 현황 기능입니다.

## 요청 범위 요약

로그인 후 상단 메뉴에 `투자 현황` 메뉴를 추가하고, 그 안에서 아래 두 영역을 볼 수 있게 해 주세요.

- `가상투자`
- `실투자`

페이지 구성은 아래 둘 중 하나로 구현 가능하지만, 1차 권장안은 하나의 컨테이너 페이지 안에서 탭으로 분리하는 방식입니다.

### 권장안

- 상단 메뉴: `투자 현황`
- 진입 경로: 예) `/me/investments`
- 페이지 내부 탭:
  - `가상투자`
  - `실투자`

### 허용안

- 별도 페이지 2개
  - 예) `/me/investments/virtual`
  - 예) `/me/investments/live`

권장 결론:

- 1차는 한 페이지 + 2개 탭 구조가 가장 자연스럽습니다.

## 사용자 기능 요구사항

각 탭(가상투자 / 실투자)에서 아래를 지원해야 합니다.

### 1. 거래 입력

사용자가 직접 입력:

- 종목코드
- 종목명
- 매수/매도 구분
- 매수/매도 수량
- 매수가/매도가
- 수수료

### 2. 종목 확인 절차

종목코드와 종목명을 사용자가 입력하면, 저장 전에 해당 입력이 정확한지 확인하는 단계가 필요합니다.

필수 요구:

- 종목코드와 종목명이 서로 일치하는지 확인
- 불일치 시 저장 불가
- 일치 시 사용자에게 확인 결과 표시

권장 UX:

- `확인됨` 상태 배지 또는 확인 메시지
- 불일치 시 `종목코드와 종목명이 일치하지 않습니다.` 오류 표시

### 3. 현재가 및 평가 계산

입력이 완료되면 시스템이 DB 또는 Quant Trading handoff 가격 데이터에서 현재가를 조회해 아래를 계산해야 합니다.

- 현재가
- 투자금액
- 평가금액
- 평가수익금액
- 평가이익률

### 4. 손익 색상 규칙

- 평가수익금액이 `+`이면 빨간색
- 평가수익금액이 `-`이면 파란색

가능하면 `평가이익률`도 같은 색 규칙을 적용해 주세요.

- 종목코드
- 종목명
- 매수/매도 구분
- 매수/매도 수량
- 매수가/매도가
- 수수료
- 투자금액
- 현재가
- 평가금액

- 평가이익률

## 권장 화면 구조

### A. 상단 메뉴

로그인 상태에서만 상단 네비게이션에 `투자 현황` 메뉴 노출

비로그인 상태:

- 메뉴 비노출 또는 클릭 시 `/login` 유도

### B. 페이지 상단 요약

탭 공통 상단에 간단한 안내 문구 표시

예:

- `이 페이지는 사용자가 직접 입력한 거래내역과 최신 가격 기준으로 평가손익을 참고용으로 보여줍니다.`

### C. 탭 구조

- `가상투자`
- `실투자`

### D. 탭 내부 블록

각 탭 내부에 아래 두 블록 권장

1. 거래 입력/수정 블록
2. 현재 평가 현황 테이블

가능하면 추후 확장용으로 아래도 고려 가능

- 거래내역 ledger 표
- 현재 보유 현황 표

## 권장 데이터 표현

### 거래 입력 단위

한 줄 거래는 아래 개념을 갖는 것이 좋습니다.

- 거래일
- 계정유형: `virtual` / `live`
- 종목코드
- 종목명
- 거래구분: `buy` / `sell`
- 수량
- 단가
- 수수료

### 평가 표시 단위

사용자 화면의 현재 평가 표는 종목 기준 aggregation으로 보여주는 것이 권장됩니다.

예:

- 종목코드 / 종목명
- 누적 순보유수량
- 평균매입단가
- 현재가
- 투자금액
- 평가금액
- 평가수익금액
- 평가이익률

단, 1차 구현에서 거래입력 표와 현재평가 표를 함께 제공하는 것도 허용합니다.

## Quant Trading handoff 전제

이 요청은 Quant Trading 쪽 개발 완료 후 QS 반영을 요청하는 용도입니다.

QS는 Quant Trading이 제공하는 아래 handoff를 소비하는 구조를 전제로 해 주세요.

예상 handoff 범위:

- 종목코드/종목명 검증용 instrument lookup
- 사용자 거래내역 저장/조회용 authenticated API 또는 DB adapter
- 현재가 조회용 API 또는 adapter
- 평가값 계산 결과를 직접 주는 endpoint가 있으면 그 결과 우선 사용

QS 구현 시 원칙:

- 계산 로직을 QS에서 중복 구현하기보다
- 가능하면 Quant Trading handoff API/adapter를 소비

## 권장 route/API 방향

최종 경로는 QS 구조에 맞게 조정 가능하지만, 아래 정도를 권장합니다.

### Web routes

- `/me/investments`
- `/me/investments/virtual`
- `/me/investments/live`

### Backend/API examples

- `GET /api/v1/me/investments/virtual`
- `GET /api/v1/me/investments/live`
- `POST /api/v1/me/investments/transactions`
- `POST /api/v1/me/investments/validate-security`

최종 API 이름은 QS-Master 배정 후 조정 가능

## 인증/권한 요구사항

이 기능은 반드시 로그인 사용자 전용이어야 합니다.

필수 요구:

- 비로그인 사용자는 접근 불가
- 사용자별 자신의 데이터만 조회 가능
- CSRF/POST 보호 적용
- 공개 캐시 금지
- 검색엔진 노출 대상 아님

이 요청은 `QS-Platform-Auth` 검토 범위를 포함합니다.

## 공개/비공개 경계

이 기능은 공개 모델 페이지와 다릅니다.

명확히 구분해야 할 점:

- 공개 모델 정보가 아님
- 사용자 개인 거래내역/실제 투자 현황 포함 가능
- personalized data
- actual investment result 가능성 있음

따라서:

- 공개 페이지로 노출되면 안 됨
- public sitemap 대상이 아님
- public current snapshot과도 분리해야 함

## UI 세부 요구

### 종목 확인 UX

- 종목코드 + 종목명 입력
- `확인` 버튼 또는 blur 검증
- 일치 시 저장 가능
- 불일치 시 저장 금지

### 숫자 포맷

- 수량: 정수 또는 허용 소수 정책에 맞춤
- 단가/수수료/평가금액: 천 단위 구분기호 표시
- 수익률: `%`

### 손익 색상

- `평가수익금액 > 0` -> 빨간색
- `평가수익금액 < 0` -> 파란색
- `= 0` -> 기본색

가능하면 `평가이익률`도 동일한 색 적용

## 반영하면 안 되는 범위

이번 요청에 포함하지 않는 것:

- 공개 홈/공개 모델 페이지 개편
- 관리자 전용 `/admin` preview
- 자동매매 기능
- 주문 연동
- 계좌 연동 실시간 브로커 연결
- 세금 계산 고도화
- 투자 자문 문구

- 사용자 전용 `가상투자 / 실투자` 화면
- 거래 입력 UI
- 종목코드/종목명 확인 UX
- 현재가/평가손익 표시 UI
- 손익 색상 규칙 반영
- 인증/권한/비공개 처리

## 권장 담당 분배

QS-Master에서 아래처럼 분배 검토를 부탁드립니다.

- `QS-Platform-Auth`
  - 로그인 사용자 전용 접근
  - 권한/보안/세션/CSRF

- `QS-Public-Web`
  - 실제 사용자 웹 화면/메뉴/탭/표 UI
  - 단, 공개 페이지가 아니라 로그인 사용자 화면

- `QS-Quant-Handoff`
  - Quant Trading 제공 API/adapter 연결
  - 종목 검증 / 현재가 / 평가 데이터 연결

## QA 체크리스트

- 로그인하지 않으면 접근 불가
- 로그인하면 상단에 `투자 현황` 메뉴가 보임
- `가상투자`와 `실투자`가 분리되어 보임
- 종목코드/종목명 불일치 시 저장 실패
- 저장 후 현재가 조회와 평가 계산이 정상 동작
- 평가수익금액 양수는 빨간색, 음수는 파란색
- 다른 사용자의 데이터는 조회되지 않음
- 공개 페이지/비로그인 페이지에는 노출되지 않음

## Acceptance Criteria

1. 로그인 사용자에게만 `투자 현황` 메뉴가 노출된다
2. `가상투자`와 `실투자` 현황을 각각 확인할 수 있다
3. 사용자가 종목코드/종목명을 입력하면 저장 전 정확성 확인 절차가 있다
4. 사용자가 수량/단가/수수료를 입력할 수 있다
5. 저장 후 현재가를 기준으로 평가금액/평가수익금액/평가이익률이 계산된다
6. 평가수익금액이 `+`면 빨간색, `-`면 파란색으로 표시된다
7. 페이지는 비로그인 사용자나 공개 경로에 노출되지 않는다
